## 一、代码规范

### 1. 花括号风格

- 所有**成对的花括号**，左侧花括号 `{` 必须**单独占一行**。
- **例外**：`namespace` 的左花括号必须与声明处于**同一行**。
- 多个 `namespace` **都写在一行**，且**不缩进**。

```cpp
namespace A { namespace B {

void Foo()
{
    // ...
}

}}
```

### 2. 枚举与常量（禁止魔数）

- `enum` 的**每个值**必须**详细注释用途**。
- 代码中**不允许出现魔数**，必须定义成**常量或者宏**。
- 定义的常量或宏必须**加上详细的注释描述用途**。

```cpp
// 网络连接超时时间，单位毫秒，防止请求长时间无响应
const int kConnectTimeoutMs = 3000;

// 用户角色类型
enum class UserRole
{
    kAdmin = 0,   // 管理员，拥有全部权限
    kOperator = 1, // 操作员，仅有读写业务数据权限
    kGuest = 2     // 访客，仅有只读权限
};
```

### 3. 类的成员变量

- 类的成员变量命名必须以 `m` 开头（如 `m_value`）。
- **每个类成员变量**必须有**详细的注释**说明其用途。

```cpp
class TcpClient
{
private:
    // 与服务端建立连接的套接字描述符，-1 表示未连接
    int m_socketFd;
    // 发送缓冲区，暂存待发送的数据
    std::string m_sendBuffer;
};
```

### 4. 类与方法的注释

- **每个新建的类**必须用注释说明其用途。
- 类的 **public 方法**必须用注释**详细说明其用途**。
- 方法**每个参数**必须**详细说明用途**。

```cpp
// 负责 TCP 连接的建立、收发与断开的网络客户端
class TcpClient
{
public:
    // 连接到指定服务端
    // 参数 host：服务端主机地址，支持域名或 IP
    // 参数 port：服务端监听端口，取值范围 1-65535
    // 返回值：连接成功返回 true，失败返回 false
    bool Connect(const std::string& host, int port);
};
```

### 5. 源码文件的文档注释

- **每个源码文件**必须加上文档注释。
- 注释中须写明：
  - 开发时间
  - 文件的用途描述
- 开发者邮箱：`lzwcracker@gmail.com`

### 6. 注释量要求

- 代码注释量**不少于代码的 30%**。
- **不要加无意义的注释**。

### 7. 控制流语句体格式

- `if`、`for`、`while` 等语句体**即使只有一行**，语句体也**必须单独占一行**。

```cpp
// 正确：语句体单独占一行
if (isReady)
{
    DoSomething();
}

// 错误：语句体与条件写在同一行
if (isReady) DoSomething();
```

### 8. 注释语言

- **所有注释必须使用英文**。

### 9. .h 与 .cpp / .c 文件头部

- 每个 `.h` 和 `.cpp` / `.c` 文件开头必须有**介绍该文件用法的描述**。
- 须说明**开发者**和**开发时间**。
- 开发者邮箱：`lzwcracker@gmail.com`

```cpp
// ============================================================================
// 文件用途：实现 TcpClient 的连接、收发与断开逻辑
// 开发者：lzwcracker@gmail.com
// 开发时间：2026-10-17
// ============================================================================
```

### 10.尽量少用Lambda 表达式

  如若使用遵循以下格式

- 禁止直接在参数写Lambda表达式，外置声明Lambda表达式变量再以参数变量传入函数

- Lambda表达式语句体**即使只有一行**，语句体也**必须单独占一行**

```cpp
std::vector<int> v = {5, 1, 9, 3};
auto less=[](int a, int b) 
            {
             return a > b;
            }
std::sort(v.begin(), v.end(),less); // 降序
```

## 二、测试规范

### 1. 先跑测试再改代码

- 对**不确定的功能**，必须**先跑 test**。
- **test 跑通后**才能改动代码。

### 2. 新功能必须有测试用例

- **每个新功能**必须有**相关的测试用例**。
- 设计好的测试用例**必须先和开发者确认**。

### 3. 关键路径必须有日志

- **关键路径必须添加日志**，以便**迅速、准确地定位问题**。

### 4. 描述严谨性

- 如果是**推测性描述**，必须加上 **“据推测”**，然后**加以验证**。
- 如果是**结论性文字**，**必须给出证据**。
